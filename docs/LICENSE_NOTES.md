# Sungrid Protocol — License Notes

## Inherited license

Sungrid Protocol is built on the OpenRA engine, which is licensed under the **GNU General Public License v3.0 or later**. The engine is fetched as a pinned build dependency (`engine/`, via `fetch-engine.sh`) rather than vendored into this repo — GPLv3 compliance for the engine itself is satisfied through OpenRA's own upstream distribution, same as any Mod SDK-based mod. This repo's own code (`mods/sungrid/`, `OpenRA.Mods.Sungrid/`) is distributed under GPLv3 as well (see [`COPYING`](../COPYING) at the repo root, copied from upstream OpenRA), since any executable code loaded by the engine must be GPLv3-compatible.

Practical implications:
- Any code contributed to `mods/sungrid/` or `OpenRA.Mods.Sungrid/` is distributed under GPLv3, same as upstream OpenRA.
- Mod **data** files (rules/YAML, art, audio) are not source code, so — per standard OpenRA Mod SDK convention — they can be licensed separately from the GPLv3 code if desired (see "Original asset licensing" below).
- Do not add dependencies with licenses incompatible with GPLv3 without checking compatibility first.

## EA / Command & Conquer non-affiliation

OpenRA's stock mods (`mods/ra`, `mods/cnc`, `mods/d2k`, bundled with the fetched engine) reimplement classic Westwood/EA game rules using original code, and EA has not endorsed and does not support OpenRA (this disclaimer already appears in the upstream `README.md`). Sungrid Protocol carries the same posture: it is a new game built on the OpenRA engine, and **it distributes no EA assets**.

How that holds in practice:
- `mods/sungrid` is content ported from `mods/ra`'s *gameplay data* (Phase 1) — OpenRA's own original reimplementation of the rules, not Westwood/EA files.
- The Red Alert asset files themselves (`.mix` sprite/audio archives) are never in this repo and never in a release package. The game reads them from the player's own copy under `<SupportDir>/Content/ra/v2/`, installed on first launch by `mods/sungrid-content` — either the official freeware Red Alert package or the player's own disc/Steam/Origin copy. This is the same arrangement upstream OpenRA uses.
- Remaining Red Alert-specific naming and imagery inside `mods/sungrid` (unit names tied to the C&C universe, inherited unit sprites) is temporary scaffolding being replaced pass by pass — the two sides, the sub-factions, several units, all UI chrome, cursors, and every Sungrid-original building/unit sprite have already been replaced with original content. The core inherited unit sprites and audio are Phase 7 and are still stock; alpha builds ship with them, drawn from the player's own content install as above.

## Original asset licensing (Phase 5+)

Phase 5 onward has produced original art and audio for Sungrid Protocol (all of it programmatic — see the generator scripts listed in `CLAUDE.md`'s directory map). The licensing decision below is **still open** and should be settled before it accumulates further:
- New art/audio assets can be licensed separately from the GPLv3 code if desired (OpenRA's own asset conventions distinguish code license from content license in places), but the choice should be made explicitly and documented here once decided — do not leave it implicit.
- Any third-party asset (fonts, sound effects, music) brought in from outside must have a license compatible with public redistribution, with attribution recorded in this file.
- AI-assisted art/audio generation used for prototyping should be treated as placeholder unless the specific tool/model's output terms are confirmed compatible with the project's chosen distribution license.

## Concept-art cameo sources (`docs/concept-art/cameo-sources/`)

The photographic build-menu cameos (`mods/sungrid/bits/*icon.png`, generated by `gen_photo_cameos.py` — see `docs/BACKLOG.md` issue #45) are cropped from author-supplied concept renders committed under `docs/concept-art/cameo-sources/` (`desert-base.png`, `desert_base2.png`, `grid-scene.png`). Per the "AI-assisted art/audio" bullet above, these are treated as **first-pass placeholder art** pending a real-artist pass, and the generation method should be recorded here explicitly:

- **Generation method / tool:** _to be confirmed by the author._ If these were produced with an AI image tool, record the specific tool/model and confirm its output terms are compatible with the project's chosen distribution license before any public/tagged release ships them; if hand-authored, note that here instead.
- The shipped cameos are derivative crops of these sources, so whatever license applies to the sources applies to them.

## Main menu music (`mods/sungrid/bits/intro.wav`)

The main-menu music sting is generated from scratch by `mods/sungrid/bits/gen_intro_music.py` — plain oscillator synthesis (sine/triangle pads, a plucked arpeggio, a sub bass, a filtered noise bed) and simple DSP (ADSR envelopes, a feedback delay), no sampled or third-party audio anywhere in the signal chain. Same placeholder posture as the rest of the programmatic art: a first pass, not a real composition, pending a composer/musician pass. No licensing question to track here beyond that — it's wholly original output of a deterministic script committed alongside it.
